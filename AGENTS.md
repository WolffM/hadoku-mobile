# hadoku-mobile

One Android app for every hadoku.me site. A Capacitor 8 WebView shell that opens
`https://hadoku.me/apps/` (the launcher page in hadoku_site, `src/pages/apps.astro`) and
navigates the live site from there; native code only where the web cannot go. Design and
the reasoning behind every choice: `../hadoku_site/docs/planning/mobile-app-2026-10-20.md`
(hadoku_site#470). `hadoku-task-mobile` is the predecessor and stays as it is.

## Layout

| Path | Purpose |
| --- | --- |
| `capacitor.config.ts` | `server.url`, UA suffix, System Bars insets. The whole product. |
| (no committed version) | The version is computed by CI at release time (`scripts/release-version.mjs`) and reaches Gradle and the UA suffix as `APP_VERSION_NAME` / `APP_VERSION_CODE`. Nothing in the repo is ever edited to release |
| `android/` | Capacitor-generated Android project (committed, like task-mobile) |
| `android/app/src/main/java/me/hadoku/app/MainActivity.java` | The shell: logs the two probe facts and its own pause/resume/stop, registers `PageMediaPlugin`, flushes cookies on pause, owns Back, keeps the launcher as home (a link to `hadoku.me/` or to `/apps/` itself, e.g. the sign-in page's "Continue without signing in", or the app icon's long-press "Home" shortcut in `res/xml/shortcuts.xml`, goes back to `/apps/`), opens the Library on `hadoku://library` or when offline |
| `android/app/src/main/java/me/hadoku/app/Theme.kt` | The Compose theme (Material You colours) |
| `android/app/src/main/java/me/hadoku/app/Hadoku.kt` | Native requests as the signed-in visitor (cookie read at use), `online()` |
| `android/app/src/main/java/me/hadoku/app/web/` | Page audio in the background: `PageMediaPlugin` (document-start script on hadoku.me + origin-scoped `WebMessageListener` reporting `{playing, title}`), `PageMediaReport` (parses it), `PageMediaService` (foreground service of type mediaPlayback, platform `MediaSession` + notification, wake and Wi-Fi locks while playing) |
| `android/app/src/main/java/me/hadoku/app/library/` | Library v1: catalog + episode parsing, `episode.json` records, DownloadManager orchestration, the Compose screens |
| `android/app/src/main/java/me/hadoku/app/download/` | `EpisodeDownloads`: one file from `/watchparty/media/*` into the episode dir |
| `android/app/src/main/java/me/hadoku/app/update/` | `UpdateCheck`: on resume (asks GitHub at most every 15 min; prompts for one version at most every 12 h; release builds only) reads this repo's public `releases/latest`; if its tag is newer than versionName, an "Update available" dialog opens the APK's download link in the browser |
| `android/app/src/main/java/me/hadoku/app/player/` | `PlaybackService` (Media3 `MediaSessionService`: the one player, background audio, lock-screen controls, saved position) and `PlayerActivity`, the screen that connects to it |
| `android/app/src/test/` | JVM unit tests |
| `android/app/src/androidTest/` | Instrumented tests; `assets/episodes/fixture-s01e01` is a synthetic episode |
| `e2e/` | Playwright driving the real WebView inside the installed debug APK |
| `scripts/` | `emulator.sh`, `emulator-sign-in.mjs`, the device-test scripts, `make-fixture-episode.sh`, `release.mjs` (dispatches a release), `release-version.mjs` (computes one) |
| `www/` | One placeholder page. Never shown: `server.url` replaces it |

## Commands

```sh
pnpm install
pnpm sync                      # cap sync android: copies capacitor.config.ts into the APK
pnpm android:build             # debug APK → android/app/build/outputs/apk/debug/app-debug.apk
pnpm android:release           # release APK; signed only with the keystore env (see CI)
pnpm release patch|minor|major|X.Y.Z  # dispatch build-apk.yml on main: CI computes the version, tags, publishes the signed APK
```

Always name Gradle tasks with `:app:`. Unqualified tasks also run in the generated
`capacitor-cordova-android-plugins` module, whose androidTest fails a duplicate-class check
on two old Kotlin stdlibs; that module is regenerated by `cap sync` and has no tests of ours.

Building needs JDK 21 and an Android SDK with `platforms;android-36` + `build-tools;36.0.0`.
On hokon the SDK is at `~/Android/Sdk` (installed 2026-10-20 with the command-line tools);
`android/local.properties` points at it and is gitignored. An emulator AVD named `spike`
(API 36, google_apis, x86_64) exists there; `pnpm emulator` boots it headless if nothing is
on adb, and every device command below calls it first. It stays up between commands but not past
the session that used it: each call registers its session (`CLAUDE_PID`, else the terminal's
session leader) and a watcher stops the emulator once none is alive. `pnpm emulator:stop` stops it
now. One left behind by a finished session ran 41 hours on hokon (2026-11-21 to 11-23).

## Tests

| Layer | Command | Runs where | What it proves |
| --- | --- | --- | --- |
| Typecheck | `pnpm typecheck` | CI `build` | config + e2e suite compile |
| Unit (JVM) | `pnpm test:unit` | CI `build` | episode layout, catalog / index.json / tracks.json parsing (on Frieren's real metadata), the Library's records, the page's media report, the update check's release parsing (on v0.1.7's real `releases/latest`) and version comparison |
| Instrumented | `pnpm test:device` | emulator | the player plays the fixture (tracks, languages, subtitles, seek, no drift); an episode longer than the player reads ahead shows its length from the start, seeks past the buffer and ends; a saved episode plays, resumes and deletes; playback carries on after Home and screen-off, answers the system media keys, returns from the notification and stops on Back; the Library link opens the Library and its back arrow returns; no network at launch opens the Library |
| Real media | `pnpm test:player-real [media id or dir] [s]` | emulator / phone | the same four tests on a real episode fetched from production (default Frieren s01e01, 180 s): its length is index.json's from the start, and the seek and pace check run 60% of the way in |
| Shell e2e | `pnpm e2e` | emulator | launcher, bridge, UA, locked tiles, tile → site → Back, Back exits, the "Home" shortcut (warm and cold), sign-in form, "Continue without signing in" returns to the launcher |
| Background audio e2e | `pnpm e2e:background` | emulator, ~6 min | a page's detached `new Audio()` plays on through 4 min of Home + screen-off with the process never in the freezer's list and `currentTime` keeping pace with the wall clock; the notification carries the page title; navigation stops it; `cmd media_session dispatch pause/play` pause and play an autoplaying in-document element; a muted video never resumes it |
| Signed-in e2e | `pnpm e2e:signed-in` | emulator, by hand | cookie reaches native code and not page JS, is on disk from the first page load (survives an immediate kill), follows into sites; the launcher shows the session after Back, after a link home, and once the network returns |
| Download resume | `pnpm emulator:sign-in`, then `pnpm test:download-resume [file] [n]` | emulator | a real file through the edge survives n airplane-mode cuts, byte-identical to the origin |
| Library live | `pnpm emulator:sign-in`, then `pnpm test:library-live [path]` | emulator | "usable on a flight": browse, download (~560 MB), sha256 = content_token, airplane mode, cold launch, watch |

- CI compiles the instrumented tests (`:app:assembleDebugAndroidTest`) so they cannot rot,
  but does not run anything on an emulator: that needs a runner with KVM, which the fleet
  has not been asked for.
- **While Playwright holds the page the WebView never reports it hidden**, so nothing that
  reacts to `visibilitychange` (the launcher re-checking whoami on resume) can be observed
  from a test; that path was checked by hand.
- **The e2e harness** (`e2e/app.ts`) resets the app with `pm clear` before every test,
  launches it over adb, and attaches Playwright's `_android` to the WebView by pid. Debug
  builds have WebView debugging on (Capacitor's default), which is what makes this possible;
  a release APK cannot be driven. Native facts come from the `HadokuShell` logcat probe.
- **Signed-in tests never run unattended.** They sign in for real and leave a 30-day
  session in production for that identity, so they fail loudly without `HADOKU_E2E_KEY`
  instead of skipping. The key is the friend-tier `KEY_FRIEND_MOBILE_E2E`, fetched by
  dev-vault (`.devvault.json`) with this repo's own service key in `.devvault.local.json`
  (gitignored, minted by the operator). Never borrow another repo's vault identity.
- **`@LiveProduction` tests** (the download spike, the Library acceptance) move real bandwidth through production
  with a real session; Gradle excludes them from `pnpm test:device` and each runs only
  through its own script. They need the emulator signed in first (`pnpm emulator:sign-in`,
  which survives until something runs `pm clear`, e.g. `pnpm e2e`).
- **The fixture** is regenerated with `scripts/make-fixture-episode.sh`, which copies
  watchparty's ffmpeg flags (`processing_meta.json`, schema v3-fragmented-audio), including
  the per-language sample rates and the QuickTime chapter track inside each audio file.
  Change the flags there if watchparty's ingest schema changes.
- **Two fixtures, and the long one is not optional.** `fixture-s01e01` (20 s) is read to its end
  the moment it opens, so the player measures its length itself; `fixture-long` (150 s, 2.5 MB of
  video) is not, like every real episode. ExoPlayer stops reading ahead at 50 s buffered but checks
  only once per megabyte, so a long episode of a few hundred KB is still read whole and tests
  nothing; `FullLengthEpisodeTest` asserts its own premise (buffered well short of the end).
- **`pnpm test:player-real` fetches its own episode and imports it as the app.**
  `scripts/fetch-episode.mjs` (needs `HADOKU_E2E_KEY`, so the script runs under dev-vault) takes
  it from production the way the app's download does: one whole-file GET per file, rate-limited,
  never a Range (the edge answers a Range on a large file with the whole file often enough to
  matter; hadoku-watchparty AGENTS.md "Edge Range collapsing"), each file checked against
  index.json's `part_sha256`, cached under `~/.cache/hadoku-mobile/episodes` and re-fetched when
  the server's `content_token` changes. It moves 300-800 MB through production: one episode, never
  a loop. The files are pushed to `/data/local/tmp` and the TEST copies them into the Library and
  writes the record with `EpisodeInfo.parse`, for two reasons: a dir the shell creates under the
  app's external files dir is not readable by the app (the player fails with "no output_frag.mp4"),
  and without a record the player has no length for the episode, so the old version of this test
  seeked to a target computed from "unknown" and passed.
- **The pace check fails on a loaded host, and its log line says which kind of slow it was.**
  hokon doubles as the CI backstop; at a load of 40-90 on 12 cores the emulator's software decoder
  ran the real 1080p episode 2.5-14 s behind in 60 s, and within 20 ms once the load fell to ~20.
  `rebuffers=0 audioUnderruns=0` on the `played … ms` line means the device was starved; rebuffers
  mean the player was waiting on the file, which is a real fault. Check `uptime` before believing
  a failure there. `ONLY=<test method>` runs one of the four.
- **A release APK on the emulator blocks every debug install** (`INSTALL_FAILED_VERSION_DOWNGRADE`:
  a release's versionCode is 1006 and up, a debug build's is 1); a test run after a failed
  install drives the old release. `adb uninstall me.hadoku.app` first.
- Screenshots the player tests take land in
  `/sdcard/Android/data/me.hadoku.app/files/test-screenshots/<mediaId>/`.

## CI, secrets and the fleet

- `build-apk.yml` is the gate AND the ship path: every push and PR builds a debug APK
  (artifact `hadoku-debug-apk`, versionName `0.0.0-dev`, versionCode 1).
- **Releasing is the operator's moment and edits nothing.** `pnpm release patch` (or
  `minor`, `major`, an exact `X.Y.Z`) runs `gh workflow run build-apk.yml --ref main -f
  release=<arg>`. That run reads the newest `vX.Y.Z` tag on origin, steps it, runs the full
  gate, builds the signed APK with versionName = the version and versionCode =
  major*1e6 + minor*1e3 + patch (so it rises past every earlier release; v0.1.5 was 1005),
  then creates the `v<version>` tag and the GitHub Release on the sha it built. Never edit a
  version into a file and never push a `v*` tag by hand: a pushed tag triggers nothing. hadoku_site's `repo-policy-manifest.json` requires the `build` context on
  `main`, and `ci-watch` watches this workflow. Runners come from the fleet via
  `vars.CI_RUNNER`, which mgmt-api writes; never hardcode a runner label.
- **Four repo secrets, none typed by hand.** `KEY_SERVICE_MOBILE` is the identity
  `mobile-service-key` (vault + edge-router registry, repo-associated; `report-job` presents
  it), seeded by mgmt-api's `POST /keys/seed-github-secret` and kept fresh by rotation
  (`IDENTITY_OVERRIDES` in `key-rotation.ts`). `HADOKU_MOBILE_KEYSTORE_BASE64`,
  `HADOKU_MOBILE_KEYSTORE_PASSWORD` and `HADOKU_MOBILE_KEY_PASSWORD` are vault items landed
  through `provision-secret` and mirrored here with `gh secret set`; the vault is the source,
  the repo copy is derived. Alias `hadoku-mobile` is not a secret and lives in the workflow.
  The keystore is PKCS12, which has one password: the workflow signs with
  `HADOKU_MOBILE_KEYSTORE_PASSWORD` for the key too. `HADOKU_MOBILE_KEY_PASSWORD` was
  generated but never applied to the key (keytool ignores `-keypass` for PKCS12), so
  nothing reads it; v0.1.0's tag build failed on it, which is why v0.1.1 is the first
  release.
  A keystore change is `provision-secret` on a NEW name plus a workflow edit — rotation of a
  signing key is an app-identity change on the phone, so it is never done casually.
- Release signing reads `KEYSTORE_FILE` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`
  from the environment (`android/app/build.gradle`). With none set, `assembleRelease` yields
  an UNSIGNED APK rather than failing.
- Enrolment record: hadoku_site commit "fleet: enrol hadoku-mobile" (2026-10-21).

## How the shell works, and what it must not do

- **The page is the app.** `server.url` makes the WebView first-party on hadoku.me, so `/auth`
  sets `hadoku_session` (`Domain=.hadoku.me; HttpOnly; Secure; SameSite=Strict`, 30 d sliding)
  exactly as in Chrome, and every site behind a tile reads it. There is no sign-in code here.
- **Nothing is stored by the app.** No key, no token. Native code that needs the session reads
  it from `android.webkit.CookieManager.getInstance().getCookie("https://hadoku.me")` at the
  moment of use and sends it as a `Cookie:` header. HttpOnly hides the cookie from page
  JavaScript, not from the native cookie store — which is also why a download must be
  enqueued natively, never from a page-fed plugin.
- **Never log a cookie value.** `MainActivity` logs presence (`hadoku_session=present|absent`)
  and whether `window.Capacitor` exists. The other `HadokuShell` lines are lifecycle
  (`activity paused|resumed|stopped`) and the page-media keep-alive
  (`page media keep-alive started|paused|resumed|title|stopped reason=…|refused|control=…`), so
  a page that went quiet in the background is diagnosable from `adb logcat -s HadokuShell`.
- **`server.url` is a works-but-unsupported Capacitor mode** (its docs say "not intended for
  production"). Keep `CapacitorHttp.enabled` and `CapacitorCookies.enabled` at their `false`
  defaults, never set `server.hostname` to the remote domain, keep `allowNavigation` empty.
  The site does not depend on Capacitor, so if a future major breaks this mode the port to a
  bare WebView is this one activity.
- **All browser traffic goes through `hadoku.me/<prefix>/*`**, never `*.hadoku.me` direct
  subdomains (platform rule; see `../hadoku_site/AGENTS.md`).

## Page audio in the background

- **Without a foreground service the freezer stops the page.** Measured on the `spike` emulator
  (API 36), 2026-11-22, on v0.1.6: a page's `<audio>` played in the app, then Home + screen-off;
  `am_freeze [pid,me.hadoku.app]` landed 66 s after `screen_toggled: 0`, at oom adj 900 (cached),
  and the process stayed in `dumpsys activity`'s "Apps frozen" list until the screen came back.
  That is the "stops after a minute or two" report from a Pixel 8a. With `PageMediaService` the
  same run was never frozen in 4 min, sat at adj 200, and the page played 248.8 s of 249.3 s
  (232.5 of 250 in a run at a host load of 160: the emulator starving, not a freeze). Capacitor does not pause the WebView
  (`KeepRunning` defaults to true, so `handlePause` never calls `onPause`/`pauseTimers`); the
  freezer is the whole cause. Chrome survives the same page because it runs a mediaPlayback
  foreground service for a playing tab, which is what `PageMediaService` does.
- **How the page tells us.** `PageMediaPlugin` is a Capacitor plugin only so it loads before the
  first page; its document-start script (hadoku.me only, main frame only) wraps
  `HTMLMediaElement.prototype.play` (a detached `new Audio()`, as a music player page uses, never reaches a
  document listener) and capture-listens for `play` in the document (autoplay), then posts
  `{playing, title}` when "anything audible playing" changes. It uses
  `WebViewCompat.addWebMessageListener` with the hadoku.me origin rule, not a
  `@JavascriptInterface` (which every frame of every origin could call); the notification's
  play/pause go back over that frame's reply proxy. Muted or volume-0 media does not count.
- **A pause keeps it for `GRACE_MS` (2 min).** A foreground service cannot be started from the
  background, and a player pauses for a moment at every track change and dropped-stream retry
  (one player backs off up to 64 s), so stopping on every pause would end the night at the first
  track change. A navigation (`onPageStarted`, in MainActivity's listener: a listener a plugin
  adds in `load()` is dropped, because `Bridge.Builder.create()` replaces the bridge's listener
  list after plugins load) or the activity's end stops it at once. A page that
  starts playing while the app is already in the background with no keep-alive left is refused
  (`keep-alive refused` in logcat) and plays only until frozen.
- **Locks only while playing.** A partial wake lock and a `WIFI_MODE_FULL_HIGH_PERF` Wi-Fi lock,
  what ExoPlayer's `WAKE_MODE_NETWORK` takes for streamed media: the players read their file in
  4 MB range chunks as they go. The emulator cannot show radio power-saving, so this one rests on
  ExoPlayer's practice, not a measurement.
- **Android WebView has no Media Session API** (`MediaMetadata` is undefined), so the title is
  `document.title`; the script reads `navigator.mediaSession.metadata` first in case that changes.

## The Library

- **The way in is watchparty.** There is no app bar: the WebView has the whole screen. Watchparty's
  lobby renders a Library link only when the user agent carries `HadokuApp/`; it points at
  `hadoku://library` (`LibraryActivity.LINK`), which `MainActivity` intercepts and never loads.
  A launch with no network opens the Library directly. Its back arrow (and Back) returns to the page.
- **Where things live.** An episode is `getExternalFilesDir("episodes")/<mediaId>/`: the files
  exactly as watchparty lays them out, plus `episode.json` (choices, per-file download ids and
  state, `content_token`, saved position). No database: delete is one directory, space used
  is one walk. `<mediaId>` is the catalog id, the path under watchparty's media root.
- **One path to the truth.** `Downloads.refresh` reconciles every record with DownloadManager;
  the Library screen calls it every second while visible and `DownloadReceiver` on
  `DOWNLOAD_COMPLETE`. A file that fails `ERROR_CANNOT_RESUME` is re-fetched only if
  `index.json`'s `content_token` is unchanged; otherwise the episode says to delete and
  download again (never splice two encodes).
- **Reads `tracks.json`, not `/api/media/<id>/tracks`**: the API keeps only English
  subtitles for the watchparty UI.
- **Playback lives in `PlaybackService`**, not the activity. A controller asks for an episode
  by mediaId alone; the service's `onSetMediaItems` fills in title and saved position from
  `episode.json`, and the service is the only writer of `positionMs`. Leaving the screen
  with Back stops; any other way keeps playing as audio (video track disabled until the
  screen returns). The service is not exported: system controls use the session's platform
  token. Instrumented tests read the service's ExoPlayer (`PlaybackService.player`) for
  exact positions and decoder counters.
- **The player gets an episode's length from `episode.json`, not from the file.** Watchparty's
  `output_frag.mp4` states no duration (empty moov, no mehd, no sidx: its own player reads
  `index.json`). Left alone ExoPlayer learns the length only after reading the file to its end,
  and until then the time bar shows a total of 00:00 and does not move, on every real episode
  (first user report, 2026-11-16). `episodeMediaSource` wraps the video in a `ClippingMediaSource`
  ending at the record's `durationMs` (index.json's `duration_ms`). An episode with no record
  plays without a known length.
- Compose is pinned to BOM 2026.06.00 (Compose 1.11): newer BOMs need compileSdk 37 and AGP
  9.1, which Capacitor 8's template does not use yet.

## Does NOT

- Does NOT bundle any site's code. Everything rendered comes from hadoku.me at run time.
- Does NOT hold secrets. The release keystore lives in the vault and reaches CI as a secret.
- Does NOT publish to npm.
- Does NOT install updates itself. `UpdateCheck` only points the browser at the new APK; the
  visitor installs it, as they installed the first one. A dev build (`0.0.0-dev`) never checks,
  so to see the prompt build with `APP_VERSION_NAME` set below the latest release.
