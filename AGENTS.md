# hadoku-mobile

One Android app for every hadoku.me site. A Capacitor 8 WebView shell that opens
`https://hadoku.me/apps/` (the launcher page in hadoku_site, `src/pages/apps.astro`) and
navigates the live site from there; native code only where the web cannot go. Design and
the reasoning behind every choice: `../hadoku_site/docs/planning/mobile-app-2026-10-20.md`
(hadoku_site#470). `hadoku-task-mobile` is the predecessor and stays as it is.

## Layout

| Path | Purpose |
| --- | --- |
| `capacitor.config.ts` | `server.url`, UA suffix, System Bars insets. The whole product. |
| `package.json` `version` | The ONLY version. Gradle derives versionName/versionCode from it, the UA suffix reads it |
| `android/` | Capacitor-generated Android project (committed, like task-mobile) |
| `android/app/src/main/java/me/hadoku/app/MainActivity.java` | The shell: logs the two probe facts, flushes cookies on pause, owns Back |
| `android/app/src/main/java/me/hadoku/app/player/` | Media3 player for a downloaded episode (Kotlin); Library builds on it |
| `android/app/src/test/` | JVM unit tests |
| `android/app/src/androidTest/` | Instrumented tests; `assets/episodes/fixture-s01e01` is a synthetic episode |
| `e2e/` | Playwright driving the real WebView inside the installed debug APK |
| `scripts/` | `emulator.sh`, `test-player-real.sh`, `make-fixture-episode.sh`, `release.mjs` |
| `www/` | One placeholder page. Never shown: `server.url` replaces it |

## Commands

```sh
pnpm install
pnpm sync                      # cap sync android: copies capacitor.config.ts into the APK
pnpm android:build             # debug APK → android/app/build/outputs/apk/debug/app-debug.apk
pnpm android:release           # release APK; signed only with the keystore env (see CI)
pnpm release patch|minor|major # bump, commit, tag v*, push: CI builds + publishes the signed APK
```

Always name Gradle tasks with `:app:`. Unqualified tasks also run in the generated
`capacitor-cordova-android-plugins` module, whose androidTest fails a duplicate-class check
on two old Kotlin stdlibs; that module is regenerated by `cap sync` and has no tests of ours.

Building needs JDK 21 and an Android SDK with `platforms;android-36` + `build-tools;36.0.0`.
On hokon the SDK is at `~/Android/Sdk` (installed 2026-10-20 with the command-line tools);
`android/local.properties` points at it and is gitignored. An emulator AVD named `spike`
(API 36, google_apis, x86_64) exists there; `pnpm emulator` boots it headless if nothing is
on adb, and every device command below calls it first.

## Tests

| Layer | Command | Runs where | What it proves |
| --- | --- | --- | --- |
| Typecheck | `pnpm typecheck` | CI `build` | config + e2e suite compile |
| Unit (JVM) | `pnpm test:unit` | CI `build` | pure Kotlin logic (episode layout parsing, …) |
| Instrumented | `pnpm test:device` | emulator | the player plays the synthetic fixture: tracks, language switch, every subtitle, seek, no dropped frames |
| Real media | `pnpm test:player-real [dir] [s]` | emulator / phone | the same test on a real pushed episode (default Frieren s01e01, 180 s) |
| Shell e2e | `pnpm e2e` | emulator | launcher, bridge, UA, locked tiles, tile → site → Back, Back exits, sign-in form |
| Signed-in e2e | `pnpm e2e:signed-in` | emulator, by hand | cookie reaches native code and not page JS, survives Home + kill, follows into sites |
| Download resume | `pnpm emulator:sign-in`, then `pnpm test:download-resume [file] [n]` | emulator | a real file through the edge survives n airplane-mode cuts, byte-identical to the origin |

- CI compiles the instrumented tests (`:app:assembleDebugAndroidTest`) so they cannot rot,
  but does not run anything on an emulator: that needs a runner with KVM, which the fleet
  has not been asked for.
- **The e2e harness** (`e2e/app.ts`) resets the app with `pm clear` before every test,
  launches it over adb, and attaches Playwright's `_android` to the WebView by pid. Debug
  builds have WebView debugging on (Capacitor's default), which is what makes this possible;
  a release APK cannot be driven. Native facts come from the `HadokuShell` logcat probe.
- **Signed-in tests never run unattended.** They sign in for real and leave a 30-day
  session in production for that identity, so they fail loudly without `HADOKU_E2E_KEY`
  instead of skipping. The key is the friend-tier `KEY_FRIEND_MOBILE_E2E`, fetched by
  dev-vault (`.devvault.json`) with this repo's own service key in `.devvault.local.json`
  (gitignored, minted by the operator). Never borrow another repo's vault identity.
- **`@LiveProduction` tests** (the download spike) move real bandwidth through production
  with a real session; Gradle excludes them from `pnpm test:device` and each runs only
  through its own script. They need the emulator signed in first (`pnpm emulator:sign-in`,
  which survives until something runs `pm clear`, e.g. `pnpm e2e`).
- **The fixture** is regenerated with `scripts/make-fixture-episode.sh`, which copies
  watchparty's ffmpeg flags (`processing_meta.json`, schema v3-fragmented-audio), including
  the per-language sample rates and the QuickTime chapter track inside each audio file.
  Change the flags there if watchparty's ingest schema changes.
- `pnpm test:player-real` installs the APKs itself: Gradle's connected tests uninstall the
  app afterwards, which deletes everything pushed under its external files dir.
- Screenshots the player tests take land in
  `/sdcard/Android/data/me.hadoku.app/files/test-screenshots/<mediaId>/`.

## CI, secrets and the fleet

- `build-apk.yml` is the gate AND the ship path: every push and PR builds a debug APK
  (artifact `hadoku-debug-apk`); a `v*` tag builds the signed release and attaches it to a
  GitHub Release. hadoku_site's `repo-policy-manifest.json` requires the `build` context on
  `main`, and `ci-watch` watches this workflow. Runners come from the fleet via
  `vars.CI_RUNNER`, which mgmt-api writes; never hardcode a runner label.
- **Four repo secrets, none typed by hand.** `KEY_SERVICE_MOBILE` is the identity
  `mobile-service-key` (vault + edge-router registry, repo-associated; `report-job` presents
  it), seeded by mgmt-api's `POST /keys/seed-github-secret` and kept fresh by rotation
  (`IDENTITY_OVERRIDES` in `key-rotation.ts`). `HADOKU_MOBILE_KEYSTORE_BASE64`,
  `HADOKU_MOBILE_KEYSTORE_PASSWORD` and `HADOKU_MOBILE_KEY_PASSWORD` are vault items landed
  through `provision-secret` and mirrored here with `gh secret set`; the vault is the source,
  the repo copy is derived. Alias `hadoku-mobile` is not a secret and lives in the workflow.
  A keystore change is `provision-secret` on a NEW name plus a workflow edit — rotation of a
  signing key is an app-identity change on the phone, so it is never done casually.
- Release signing reads `KEYSTORE_FILE` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`
  from the environment (`android/app/build.gradle`). With none set, `assembleRelease` yields
  an UNSIGNED APK rather than failing.
- Enrolment record: hadoku_site commit "fleet: enrol hadoku-mobile" (2026-10-21).

## How the shell works, and what it must not do

- **The page is the app.** `server.url` makes the WebView first-party on hadoku.me, so `/auth`
  sets `hadoku_session` (`Domain=.hadoku.me; HttpOnly; Secure; SameSite=Strict`, 30 d sliding)
  exactly as in Chrome, and every site behind a tile reads it. There is no sign-in code here.
- **Nothing is stored by the app.** No key, no token. Native code that needs the session reads
  it from `android.webkit.CookieManager.getInstance().getCookie("https://hadoku.me")` at the
  moment of use and sends it as a `Cookie:` header. HttpOnly hides the cookie from page
  JavaScript, not from the native cookie store — which is also why a download must be
  enqueued natively, never from a page-fed plugin.
- **Never log a cookie value.** `MainActivity` logs presence (`hadoku_session=present|absent`)
  and whether `window.Capacitor` exists; that is the only logging, and it stays that way.
- **`server.url` is a works-but-unsupported Capacitor mode** (its docs say "not intended for
  production"). Keep `CapacitorHttp.enabled` and `CapacitorCookies.enabled` at their `false`
  defaults, never set `server.hostname` to the remote domain, keep `allowNavigation` empty.
  The site does not depend on Capacitor, so if a future major breaks this mode the port to a
  bare WebView is this one activity.
- **All browser traffic goes through `hadoku.me/<prefix>/*`**, never `*.hadoku.me` direct
  subdomains (platform rule; see `../hadoku_site/AGENTS.md`).

## Does NOT

- Does NOT bundle any site's code. Everything rendered comes from hadoku.me at run time.
- Does NOT hold secrets. The release keystore lives in the vault and reaches CI as a secret.
- Does NOT publish to npm.
